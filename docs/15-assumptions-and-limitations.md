# Assumptions, Constraints, and Limitations

## Confirmed from the technical repositories
- Three separate public repositories exist for users, roles/permissions, and activity history.
- Their READMEs describe synthetic Excel inputs, Python processing, MySQL 8.0 schemas, validation, tests, and CI integration.
- The technical repositories document their own limitations and sample data-quality outcomes.
- The latest known workflow runs at the time this case study was assembled completed successfully.

## Planning assumptions (not independently validated by a business)
- The three workstreams are treated as one coordinated initiative for educational purposes.
- Relative durations and dependencies represent a reasonable proposed sequence.
- Stakeholder roles represent typical responsibilities that would exist in a real migration.
- The proposed hybrid approach is suitable for demonstrating both baseline control and iterative technical delivery.

## Limitations
- The project is retrospective: PM artifacts are reconstructed after the technical repositories were built.
- No contemporaneous project charter, approved schedule, time sheet, cost baseline, or meeting minutes were supplied.
- No external sponsor, customer, data owner, security reviewer, or technical reviewer participated in this case.
- RACI roles are role hats performed by one individual; they are not separate team members.
- Stakeholders are archetypes, not actual named people.
- Sample record counts are small and synthetic.
- CI validates only the scenarios configured in the repositories.
- No production deployment, real-data processing, penetration test, privacy assessment, or formal compliance audit is claimed.
- GitHub workflow artifacts may expire; durable evidence should be kept in repository documentation when appropriate.

## How to improve the evidence in a future iteration
1. Create a Jira board and enter the backlog as issues.
2. Record actual estimates, transitions, blockers, decisions, and review outcomes while work is in progress.
3. Maintain dated status reports and a decision log.
4. Conduct a real peer review and record the feedback with permission.
5. Add a source-to-target reconciliation report and rollback exercise.
6. If real data is ever used, obtain explicit authorization and complete security/privacy review first.
